SUI MULTISIG - MANUAL RECOVERY WITH THE SUI CLI
================================================

Use this when the extension, the phone page, the relay, GitHub or Cloudflare are unavailable,
or when the phone is lost (desktop key + paper backup key). Nothing here depends on this repo.
Tested end to end on localnet (build -> sign x2 -> combine -> execute).

You need: the sui CLI, any 2 of the 3 member keys (recovery phrases), and the multisig
configuration (3 public keys in order, weights, threshold). The order of the public keys is part
of the address: keep it exactly as written in config/wallet.json and on your paper backup.

Work in a throwaway keystore so your normal ~/.sui is never touched.
Do this on a computer you trust, then delete the folder.


0. Variables (fill in)
----------------------
export WORK=$HOME/sui-recovery
export MS=0x...                  # multisig address
export PK1=...                   # desktop public key (base64, from config/wallet.json)
export PK2=...                   # phone public key
export PK3=...                   # backup public key
export TO=0x...                  # where the funds should go
export RPC=https://fullnode.mainnet.sui.io:443


1. Throwaway keystore and client config
---------------------------------------
mkdir -p $WORK && cd $WORK
echo '[]' > sui.keystore
cat > client.yaml <<EOF
keystore:
  File: $WORK/sui.keystore
envs:
  - alias: mainnet
    rpc: "$RPC"
    ws: ~
active_env: mainnet
active_address: "$MS"
EOF


2. Check the address before anything else
-----------------------------------------
sui keytool multi-sig-address --pks $PK1 $PK2 $PK3 --weights 1 1 1 --threshold 2
# multisigAddress must equal $MS. If not, the key order or a key is wrong. Stop.


3. Import the two keys you have
-------------------------------
# Slush / Sui Wallet derive account N at m/44'/784'/N'/0'/0' (first account: N = 0).
sui keytool --keystore-path $WORK/sui.keystore import "word1 word2 ... word24" ed25519 "m/44'/784'/0'/0'/0'"
sui keytool --keystore-path $WORK/sui.keystore import "word1 word2 ... word24" ed25519 "m/44'/784'/0'/0'/0'"
sui keytool --keystore-path $WORK/sui.keystore list
# The two suiAddress values must match two member addresses printed by `npm run address`.
# If one does not, try the next account index (1', 2', ...) in the derivation path.
export SIGNER1=0x...
export SIGNER2=0x...


4. Build the unsigned transaction
---------------------------------
# Example: send all SUI except gas to $TO.
sui client --client.config $WORK/client.yaml ptb \
  --sender @$MS \
  --gas-budget 50000000 \
  --transfer-objects "[gas]" @$TO \
  --serialize-unsigned-transaction
# Example: send a specific object (NFT, position, cap) to $TO.
#   sui client --client.config $WORK/client.yaml ptb --sender @$MS --gas-budget 50000000 \
#     --transfer-objects "[@0xOBJECT_ID]" @$TO --serialize-unsigned-transaction
export TX=<the base64 line printed above>

# Optional: see what it does before signing.
sui client --client.config $WORK/client.yaml serialized-tx $TX --dry-run


5. Sign with both keys
----------------------
sui keytool --keystore-path $WORK/sui.keystore sign --address $SIGNER1 --data $TX --json
sui keytool --keystore-path $WORK/sui.keystore sign --address $SIGNER2 --data $TX --json
export SIG1=<suiSignature from the first command>
export SIG2=<suiSignature from the second command>


6. Combine
----------
sui keytool multi-sig-combine-partial-sig --pks $PK1 $PK2 $PK3 --weights 1 1 1 --threshold 2 --sigs $SIG1 $SIG2 --json
export MSIG=<multisigSerialized from the output>


7. Execute
----------
sui client --client.config $WORK/client.yaml execute-signed-tx --tx-bytes $TX --signatures $MSIG


8. Clean up
-----------
rm -rf $WORK


Replacing a lost phone
----------------------
A multisig address is derived from its member keys, so a new phone key means a NEW multisig
address. Set up the new key, put it in config/wallet.json, run `npm run address`, then use the
steps above (desktop key + backup key) to move every asset from the old address to the new one.
